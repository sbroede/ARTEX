# ARTEX Codex Bridge

Use Codex through an OpenAI-compatible local API, with ChatGPT sign-in managed
by the official `codex app-server`. OAuth credentials and refresh tokens stay
inside Codex. ARTEX receives only the bridge's separate API key.

This is an adapter for Codex inference, not a replacement for the full OpenAI
Platform API. Availability and usage limits follow the signed-in Codex account.
Inference requires managed ChatGPT authentication; signed-out and API-key
profiles are rejected before starting a model turn.
The implementation uses experimental app-server dynamic tools. It targets the
protocol generated by Codex CLI **0.171.0-alpha.13.2**; check compatibility before
upgrading or using a different CLI version.

## Start on the host

Requirements: Node.js 22+, an official Codex CLI with `app-server`, and an account
with Codex access. There are no npm dependencies and no Go/frontend rebuild is
needed for the bridge.

From the repository root:

```sh
cd integrations/codex-bridge
node cli.mjs login
node cli.mjs status
node cli.mjs serve
```

Complete the ChatGPT login in the browser. If `codex` is not in PATH, set
`CODEX_BIN` to its absolute executable path. For the macOS desktop installation:

```sh
export CODEX_BIN='/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex'
```

For a headless host use `node cli.mjs login --device-auth`, if enabled for your
account. Login is for a dedicated Codex profile, by default `~/.artex/codex`.
The existing desktop/CLI profile is independent. Use the same
`CODEX_BRIDGE_HOME` for login and serving if overriding that path.

The server listens on **127.0.0.1:8789**, separate from ARTEX's port 8787.
On first start it creates a random API key in `~/.artex/codex/bridge-api-key`
with owner-only permissions. Read that file locally and paste its value into
ARTEX's API Key field. Never paste a ChatGPT OAuth token into ARTEX.

## ARTEX model profile

In **System → LLM**, add a profile:

| Field | Value |
| --- | --- |
| Name | ChatGPT / Codex |
| Format | OpenAI (Chat Completions) |
| Base URL, native ARTEX | `http://127.0.0.1:8789/v1` |
| Base URL, ARTEX in Docker Desktop | `http://host.docker.internal:8789/v1` |
| API Key | The bridge key from the local key file |
| Model | An available ID from the model list |

Set `ARTEX_LLM_PRIVATE_ENDPOINTS=127.0.0.1:8789` on the ARTEX backend to allow
the UI's model-list request. In Docker use
`ARTEX_LLM_PRIVATE_ENDPOINTS=host.docker.internal:8789` instead. Restart the backend
after changing the environment. This allow-list affects model discovery;
the model profile must still contain the bridge URL and key.

On Docker Desktop, host services may need to listen on an interface reachable
from the container. If loopback is unreachable, start with
`CODEX_BRIDGE_HOST=0.0.0.0 node cli.mjs serve` and limit host firewall access to
your local Docker clients. On Linux add `host.docker.internal:host-gateway` to
the ARTEX service's `extra_hosts`, or use your host gateway address. Codex runs on
the host; no OAuth file needs to be mounted into ARTEX containers.

Click **Load available models**, select a supported model, save the profile and
**Set as active**. Do not select the Responses API format for this bridge.

## HTTP interface

Every route requires `Authorization: Bearer <bridge-key>`. Browser-origin
requests are rejected, and no CORS access is enabled.

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/healthz` | HTTP liveness; does not verify account/model access |
| GET | `/v1/models` | Live paginated Codex model catalog |
| POST | `/v1/chat/completions` | JSON or SSE Chat Completions |
| GET | `/auth/status` | Signed-in state and auth mode |
| POST | `/auth/login` | Start managed ChatGPT OAuth; returns `auth_url` and `login_id` |
| POST | `/auth/cancel` | Cancel a pending login; JSON body `{"login_id":"..."}` |

For API-driven login, open the returned URL locally and poll `/auth/status`.
Codex handles the localhost OAuth callback and renews credentials. CLI login
is the simplest setup path. Do not initiate CLI and HTTP login simultaneously.

## Behavior and compatibility

- Supports text messages, streamed text, function tools, `reasoning_effort`, and
  `response_format.type=json_schema` through Codex's output schema.
- Each completion uses a fresh ephemeral Codex thread in an empty temporary
  directory. System/developer messages become Codex instructions; other messages,
  including assistant calls and tool results, become an ordered JSON transcript.
  This preserves content but is not native Chat Completions role encoding.
- ARTEX owns tool execution. A Codex dynamic-tool request is returned as an
  OpenAI `tool_calls` response; the isolated worker is stopped without executing
  the function. The next ARTEX request supplies the result in its transcript.
  At most one tool call is returned per completion; parallel calls are serialized
  across ARTEX's agent loop. `tool_choice` supports `auto` and `none`.
- Tool names are mapped to internal names so ARTEX's tools cannot collide with
  Codex built-ins. Environment access and shell/web tools are disabled;
  unexpected built-in tool requests fail the completion.
- Actual token usage is returned when Codex reports it. A tool-call response can
  arrive before usage is reported and then has **no usage object**. ARTEX token
  budgets may undercount these calls. No usage is fabricated.
  With streaming, usage accompanies the final `finish_reason` chunk because
  ARTEX's Norma reader may stop at that chunk. It is not sent in a later
  `choices: []` chunk that the reader could miss.
- Codex does not expose Chat Completions sampling or output-token controls here.
  `temperature`, `top_p`, penalties, `max_tokens`, and `max_completion_tokens` are
  accepted for ARTEX compatibility but **not enforced**. The response header
  `X-Codex-Bridge-Ignored-Parameters` lists supplied ignored parameters. Use the
  timeout/concurrency limits and account limits for operational bounds.
- Images, audio, `stop`, logprobs, multiple choices, and forced tool choices are
  rejected. `/v1/responses`, embeddings and the other Platform API routes are not
  implemented. SSE uses Chat Completions deltas and `[DONE]`. HTTP success headers
  are delayed until real output or a successful tool call, so failures before
  output reach ARTEX as non-2xx responses. Failures after partial output terminate
  the stream without a successful `[DONE]`.
- Codex cybersecurity policy rejections (`cyberPolicy`) return HTTP 403 with code
  `cyber_policy`. They are not converted into empty successful answers. The bridge
  does not alter task contents, switch models, or change safeguards to bypass a
  service policy rejection. Account-specific security-research access must be
  handled with the service provider.
- Defaults: two concurrent workers, up to 16 waiting requests, two-minute queue
  timeout, five-minute completion timeout, 16 MiB body limit. The planner and
  workers can overlap without immediately hitting 429. A full queue returns 429;
  an expired queue wait returns 503. Disconnected requests terminate their worker
  or are removed from the queue before starting a Codex process.

| Environment variable | Default |
| --- | --- |
| `CODEX_BIN` | `codex` |
| `CODEX_BRIDGE_HOME` | `~/.artex/codex` |
| `CODEX_BRIDGE_HOST` | `127.0.0.1` |
| `CODEX_BRIDGE_PORT` | `8789` |
| `CODEX_BRIDGE_API_KEY` | Generated key file; minimum 32 characters |
| `CODEX_BRIDGE_CONCURRENCY` | `2` |
| `CODEX_BRIDGE_QUEUE_SIZE` | `16` (use `0` for immediate overload rejection) |
| `CODEX_BRIDGE_QUEUE_TIMEOUT_MS` | `120000` |
| `CODEX_BRIDGE_TIMEOUT_MS` | `300000` |

## Verification

```sh
node --test test/*.test.mjs
```

The tests launch a fake app-server over actual JSON-RPC pipes and exercise the
local HTTP API, authentication, OAuth routing, model pagination, streaming, usage,
external tool calls, process failures, disconnects, timeouts and overload. They do
not contact OpenAI or consume account quota. A real model/tool round trip also
requires completing ChatGPT login and checking the selected account/model.

References: [Codex App Server](https://learn.chatgpt.com/docs/app-server),
[Codex authentication](https://learn.chatgpt.com/docs/auth).
